# Implementation Plan: Structured Initiative Intake + SMQ + Extraction Guidance + RAG Report + Stakeholder Priority

**Branch**: `013-structured-intake-report` | **Date**: 2026-04-02 | **Spec**: [spec.md](spec.md)

---

## Summary

Add five capabilities on top of the existing Django/Next.js stakeholder analysis platform: a structured initiative intake form (replacing free-text concept notes), an 8-section Stakeholder Mapping Questionnaire (SMQ) with AI pre-fill, a per-project extraction guidance panel, section-by-section RAG report generation, and a scored stakeholder priority table with CSV export. All five capabilities extend existing models, prompts, and LLM infrastructure — no new services or dependencies are required beyond what is already in `requirements.txt`.

---

## Technical Context

**Language/Version**: Python 3.11 (Django 4.2), TypeScript (Next.js 14)
**Primary Dependencies**: Django REST Framework, sentence-transformers (all-MiniLM-L6-v2), pgvector, ReportLab, Groq/OpenAI/Gemini (existing abstraction), RapidFuzz
**Storage**: PostgreSQL 15 + pgvector (Supabase) — all new tables follow existing migration patterns
**Testing**: pytest + pytest-django (existing setup). All LLM calls mocked in tests.
**Target Platform**: Docker Compose (existing stack). No new containers.
**Performance Goals**: Single SMQ section AI generation ≤15s. Full 8-section batch ≤60s (ThreadPoolExecutor, 4 parallel). Priority table load ≤2s for 200 entities.
**Constraints**: No Celery/Redis (KISS). No new Python packages. ReportLab already in requirements.txt. All LLM calls mocked in CI.
**Scale/Scope**: Per-project (one analyst at a time). Up to 50 documents, 500 entities per project.

## Implementation Strategy

### MVP Scope (deliver in order)

1. **US-01 first** (Structured Intake): Enables `get_project_context()` which improves every other call.
2. **US-03 second** (Extraction Guidance): Simple CRUD + prompt injection. No LLM dependency.
3. **US-02 third** (SMQ): Requires data migration + AI generation per section.
4. **US-04 fourth** (RAG Report): Most complex — depends on SMQ, ThreadPoolExecutor, ReportLab.
5. **US-05 fifth** (Priority Table): Depends on existing graph data, mostly computation + UI.

### Prompt Templates

Three new prompt files in `prompts/`:

**`smq_section_generate.txt`**: Given section question prompts + top-K chunks + project context → generate an evidence-backed answer for this SMQ section.

**`report_section.txt`**: Given section title + SMQ answer for this section + top-K chunks + project context → generate a formal narrative paragraph for the stakeholder report.

**`engagement_note.txt`**: Given entity name/type + its relationships + SMQ section 2 and 6 answers + top-3 relevant chunks → generate a one-sentence engagement recommendation.

### ThreadPoolExecutor Pattern (Report Generation)

```python
# In ner/services/report_generator.py
from concurrent.futures import ThreadPoolExecutor
import django

def generate_section_task(project_id, section_id):
    django.db.close_old_connections()
    # fetch, generate, save to ReportSection
    ...

def generate_all_sections(project, section_ids):
    with ThreadPoolExecutor(max_workers=4) as executor:
        futures = [
            executor.submit(generate_section_task, str(project.id), str(sid))
            for sid in section_ids
        ]
    # Results are already saved to DB by each thread
```

### Frontend Polling Pattern

```typescript
// ReportSectionCard polls every 2s while any section is 'generating'
useEffect(() => {
  if (sections.some(s => s.status === 'generating' || s.status === 'pending')) {
    const timer = setInterval(fetchStatus, 2000);
    return () => clearInterval(timer);
  }

```
